# 票据置信分放行阈值调参与验收

财务拟用候选引擎 **B 的置信分** 决定票据放行，人工真值用于离线调参与验收。本系统把「调参—封存—验收—交付」做成一条不可跳过的闭环，全部规则由后端强制，前端只负责呈现。

仅依赖 **Python 3.11 标准库**（`http.server` + `sqlite3`），无第三方包、无需 Docker；前端为原生 HTML/CSS/JS。

## 业务规则与实现对照

| 业务要求 | 系统约束 |
|---|---|
| 导入 B 分数和人工真值 | CSV 六列：批号、票号、票种、B 置信分（0–100）、A 是否放行、人工真值是否合格；逐行类型/范围校验 |
| 调参批与验收批不得共用批号或票号 | `datasets.batch_id` 全局唯一；`ticket_index` 登记全部票号，跨批重复即拒绝（`services/datasets.py`） |
| 每票种在错放上限内选合格放行最多的阈值，相同取更严 | `domain.select_thresholds`：候选阈值为本批出现过的分数加「不放行」哨兵，先按错放≤上限过滤，再最大化合格放行数，并列时取分数更高者 |
| 先只用调参批封存阈值，再读验收批 | 首版封存前，验收批导入直接 400；阈值只允许在 `role=tuning` 的批次上拟合/封存 |
| 验收：各票种错放均不超限 **且** B 比 A 多放行合格票才通过 | `domain.evaluate_acceptance`：逐票种核对 cap，合格放行总数严格比较 `B > A` |
| 并发验收同批只认一套已封存阈值 | 验收批首次揭晓时与当时生效阈值版本绑定（`acceptance_batches`），同批所有尝试共用该版本 |
| 调参更正后换没揭晓的新批再验 | 再次封存会把旧版置 `superseded`；已揭晓批次绑定版本不同时拒绝再次发起，必须导入新验收批 |
| 中断后续跑沿用原阈值和数据版本 | 尝试记录固化 `threshold_set_id` 与 `dataset_checksum`；租约过期置 `interrupted`，续跑新建尝试但两标识不变，数据指纹不一致即中止 |
| 旧尝试不得发布 | 封存新版本时，旧版本上所有尝试立即 `publishable=0`；导出接口对不可发布尝试返回 409 |
| 验收页面和导出同版列出阈值、批次、合格放行数、错放数 | 页面与 CSV 均读取完成时封存的 `result_json`，不重新计算；导出含阈值版本、批号、SHA-256 指纹与逐票种四项指标 |

## 启动

```bash
cd credit-release
python3 -I run_server.py
# 浏览器访问 http://127.0.0.1:18372
```

环境变量（均有默认值）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `CR_HOST` / `CR_PORT` | `127.0.0.1` / `18372` | 监听地址 |
| `CR_DATA_DIR` | `./data` | SQLite、导出文件、签名密钥目录 |
| `CR_SEED_DEMO` | `true` | 启动时写入演示账号与三个演示批次 |
| `CR_LEASE_SECONDS` | `30` | worker 租约时长，过期视为中断 |

演示账号（首次启动自动创建）：

| 角色 | 账号 / 口令 | 权限 |
|---|---|---|
| 复核主管 | `admin` / `admin-demo-2611` | 封存阈值、查看审计、全部读写 |
| 分析员 | `analyst` / `analyst-demo-2611` | 导入数据、发起/续跑验收、导出 |
| 只读查看 | `viewer` / `viewer-demo-2611` | 查看页面、下载可发布报告 |

## 操作流程

1. **数据批次**页导入调参批 CSV（模板可直接下载）；此时导入验收批会被拒绝。
2. **阈值封存**页选择调参批与每票种错放上限，预览全部候选阈值的合格放行/错放权衡及入选标记，由复核主管封存 v1。
3. 导入验收批（批号、票号与调参批互斥）。
4. **运行验收**页揭晓验收批——揭晓即绑定 v1 并不可换；可并发发起多次尝试，全部使用同一封存版本。
5. **验收结果**页查看逐票种阈值、合格放行数、错放数与通过结论；可发布尝试可导出同版 CSV。
6. 若需调参更正：复核主管封存 v2 → v1 上的历史尝试立即失去发布资格 → 已揭晓批次拒绝复验 → 导入未揭晓的新验收批绑定 v2 再验。
7. 进程中断的尝试标记为「已中断」，续跑沿用原阈值与数据指纹；审计页可追溯全部关键动作。

## 测试

```bash
python3 -I run_tests.py
```

- `tests/test_domain.py`：阈值选择（上限约束、并列取严、无可行阈值封锁）、验收判定（超限/非严格占优拒绝）、CSV 校验。
- `tests/test_services.py`：封存前禁入验收批、批号票号互斥、并发同批一套阈值、中断续跑指纹不变、更正封存后旧尝试不可发布、换批绑定新版本、审计留痕。
- `tests/test_http.py`：真实起 HTTP 服务，覆盖鉴权、角色权限、全链路 API、导出 409 与同版内容。

## 数据与安全说明

- SQLite 位于 `CR_DATA_DIR`，写操作经进程锁串行化，WAL 模式；删除该目录即完全重置。
- 令牌为 HMAC-SHA256 签名（密钥存于 `data/secret.key`，权限 600），口令用 PBKDF2-SHA256 摘要存储。
- 所有输入文件视为不可信数据：CSV 严格解析、数值范围校验、导出对公式注入字符加前缀。
